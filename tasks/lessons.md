# Lessons

[2026-07-03] [OrcaVoice] Mistook Blabby's trigger as forward slash from dictation wording → Verify local config/keycodes first; keycode 220 maps to backslash (`\\`), not forward slash (`/`).
[2026-07-25] [OrcaVoice] Assumed "doesn't start on startup" meant a missing Run entry; the entry existed and the app *was* launching, but a blank tray icon plus a hidden window made it invisible → For tray apps, check visibility (tray icon set, window hidden) before assuming the launcher failed.
[2026-07-25] [OrcaVoice] Duplicate instances silently fought over the global hotkey, leaving dead processes that broke dictation → Any app owning a global hotkey must register tauri-plugin-single-instance first, before other plugins.
[2026-07-25] [OrcaVoice] `cargo build --release` produces a DEV binary: tauri's build.rs sets `dev = !custom_protocol`, so without `--features custom-protocol` the "release" exe ignores its embedded assets and loads `devUrl` (localhost:1420). It silently rendered whatever a leftover vite dev server was serving (an old, deleted GUI) and showed a blank dark chrome-error page once vite died → Always build desktop artifacts with the Tauri CLI (`tauri build`), never bare cargo. Autostart pointed at that dev binary, so the bug only ever appeared outside `tauri dev`.
[2026-07-25] [OrcaVoice] Chased three wrong root causes (stale cargo cache, CSP, transparency) before instrumenting `on_page_load` to a log file, which showed `url=http://localhost:1420/` in one line → When a webview renders blank, get the loaded URL first; screenshots and rebuild timings cannot distinguish "wrong page" from "broken page".
[2026-07-25] [OrcaVoice] Shipping shortcuts/autostart that point into `src-tauri/target/release/` breaks the moment the project folder moves or a dev build overwrites the exe → Install to `%LOCALAPPDATA%` via the NSIS bundle and point every shortcut and the Run key at the installed path; keep the OneDrive copy as the installer only.
[2026-07-25] [OrcaVoice] Windows can disable a Run entry independently via `Explorer\StartupApproved\Run`, and tauri-plugin-autostart reports autostart as OFF when that override is set → When verifying autostart, check both the Run key and the StartupApproved bytes, not just the Run key.
[2026-07-25] [OrcaVoice] Docs described removed features (OpenAI switching, provider benchmark, `Ctrl+Shift+Space`) and a README screenshot showed a long-dead UI, which is what made the stale-GUI bug so confusing to diagnose → When removing a feature, grep docs/ and README in the same change; regenerate UI screenshots from the running build.
[2026-07-25] [OrcaVoice] `generate_context!` embeds `dist/` at compile time, but `tauri_build::build()` only registers the config as a build input, so a frontend-only change can leave cargo thinking the crate is fresh → build.rs emits `cargo:rerun-if-changed` for every file under the frontend dist.
[2026-07-25] [OrcaVoice] Retired settings keys (openai, parakeet) lingered in settings.json because serde ignores unknown fields on read → Rewrite the settings file on load whenever it differs from the canonical serialized shape.
[2026-07-28] [OrcaVoice] The overlay stayed pinned open after the second hotkey press because `hideOverlay()` existed only on the success path; any error (silent/short recording, Groq failure) landed in a catch that re-showed the bubble and never hid it, and compact mode renders no error text, so it looked like a stuck switch → Every terminal state, success and failure, must schedule the hide; route it through one cancellable timer so a stale hide can never fire mid-recording.
[2026-07-28] [OrcaVoice] The overlay-stays-pinned bug had already recurred once because nothing tested the frontend at all — `npm test` only ran `cargo test` → Regression-prone UI state machines need a test at the same level the bug lives; mock `@tauri-apps/api/core` invoke, use fake timers, and prove each guard by mutation (delete it, watch the intended test go red) before claiming coverage.
[2026-07-28] [OrcaVoice] The overlay flashed red-after-success because `history.json` was 94,916 NUL bytes (crash-during-write), and `append_history` ran AFTER the paste inside `stop_and_transcribe`, so every dictation pasted its text and then returned Err → the red "error" state was real. Two rules: (a) a side-effect that runs after the user already has their result must never fail the operation — log it and return a partial success; (b) any file the app rewrites in place needs an atomic temp+fsync+rename, because `fs::write` truncation plus a forced kill yields a correct-length, all-NUL file that then fails forever.
[2026-07-28] [OrcaVoice] Ran `git checkout src/App.tsx` to undo a one-line mutation test and destroyed every uncommitted change in that file (it reverted to a commit predating the whole feature) → Never use `git checkout`/`restore` to undo a scratch edit on a dirty working tree; copy the file to a backup first and restore from that copy. The test suite is what proved the manual reconstruction was complete.
[2026-07-28] [OrcaVoice] Two functionally different binaries both shipped as "0.2.0", so the stale desktop installer was indistinguishable from the fixed one and got run by mistake → Bump the version on every behavioural fix and keep exactly one installer on the desktop; move superseded ones into an archive folder so they cannot be double-clicked.
[2026-07-28] [OrcaVoice] Reported the overlay-hide bug as fixed after `npm test` went green, but the user was running the INSTALLED exe from three days earlier — `npm test` only rebuilds `dist/`, never the binary, so the fix had never executed on their machine → A frontend fix is not shipped until `npm run tauri:build` + reinstall; verify by comparing the installed exe's mtime against the source change and confirming the new `dist/assets/*.js` hash is embedded in the exe.
[2026-07-28] [OrcaVoice] Windows repeats `WM_HOTKEY` while the trigger key is held and `global-hotkey` emits a `Pressed` event per repeat; `hotkey.rs` called `window.show()` on every one, so Rust force-showed the overlay with no matching hide and could re-show it after the UI hid it → Edge-trigger global hotkeys with a pressed/released latch so one physical press is exactly one toggle; never let the backend force visibility on a repeatable event.
[2026-07-28] [OrcaVoice] Set an `inFlight` latch before an `await` that sat OUTSIDE the try/finally, so one rejected IPC call wedged the latch true forever and silently dropped every later hotkey press → A guard flag must be set and cleared in the same try/finally; any `await` between the two belongs inside the try.
[2026-07-03] [OrcaVoice] Over-engineered sound/ducking with WebAudio, Beep, and raw COM volume changes before matching Blabby's working timing → For global-hotkey SFX, use native WAV playback; play start SFX before ducking; always restore audio sessions on stop/cancel/startup.
